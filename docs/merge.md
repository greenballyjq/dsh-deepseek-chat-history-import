# 合并、去重与版本取舍

多个导出文件一起导入时，插件会把它们当成同一批来源合并，而不是简单拼接。

## 1. 什么算同一段对话

只看 **对话 id**：

- 官方导出：`id`
- 浏览器记录：`data.chat_session.id`

以下都**不算**同一段：

- 标题相同但 id 不同
- 文件名相同
- 字节大小相同
- 内容 99% 相似但 id 不同

不同 id 的对话全部保留，哪怕标题一样。

## 2. 同一个 id 的多份，取哪份

按顺序：

1. `updated_at` 较新的
2. 时间相同：比较语义内容
   - 内容相同 → 重复，保留一份
   - 内容不同 → 看导出日期：
     - 有可信导出日期（ZIP 文件名里的 `YYYY-MM-DD`）→ 取较晚的
     - 没有 → 取消息更多、内容更完整的那份
     - 仍然分不出 → 标记**冲突**，按来源顺序保留第一份
3. 官方与浏览器记录同 id：
   - 时间不同：时间新者胜
   - 时间相同：官方优先

**不会把两个版本的消息拼在一起。** 整段取一份，避免分支和顺序不可预测。

内容比较会忽略 JSON 键顺序与格式化，只比较标题、消息/分支内容、消息时间等语义字段。

## 3. 只在一份里出现的对话

默认**全部保留（并集）**：

- 只出现在旧文件：保留，标「旧版独有」
- 只出现在新文件：保留，标「新版独有」
- 两边都出现：按第 2 节取一份

理由：

- 导出文件没有删除标记，无法可靠区分“被删了”和“这份文件没包含”
- 单文件、浏览器记录这类不完整来源，缺失不代表删除
- 静默丢数据比多留一段更难发现
- 只想看当前状态时，只选最新那份即可

「旧版独有 / 新版独有」标签只在**所有来源都是带日期的官方 ZIP** 时显示；混合来源、JSON、单文件不猜新旧。

## 4. 计数

- **唯一对话**：合并后的 id 数
- **重复**：同一 id 第二次及以后出现的次数
- **更新**：重复项里内容确实不同的数量
- **冲突**：时间相同、内容不同、且无法按日期/长度分出胜负的数量
- **跳过**：无法识别、损坏、缺失的文件或条目，附原因

两个完全相同的文件：唯一数等于一份，重复数等于另一份的对话数，更新 0。

## 5. 典型例子

### 两个内容完全相同的 ZIP

- 唯一：N
- 重复：N
- 更新：0
- 旧版独有 / 新版独有：0

### 10 月快照 + 11 月快照

11 月删了 2 段、改了 3 段、新增 5 段，10 月有 2018 段：

- 唯一：2018 + 5 = 2023
- 重复：两边都出现过的 2016
- 更新：3
- 旧版独有：2（被删的，保留）
- 新版独有：5

### 同名不同内容

文件名不参与判断，按 id 合并。

### 同一文件里同 id 出现两次

同样按第 2 节取新，计入重复。

## 6. 限制

- 这是**合并策略**，不是官方账单或官方删除记录
- 「更多消息」是启发式，不保证一定更新
- 冲突时保留第一份，是为了确定性；面板会显示冲突数
- 不按标题、文件名、内容相似度合并
- 不拼接两个版本的消息
