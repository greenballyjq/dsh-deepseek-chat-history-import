# 常见问题

## 文件与上传

### 选了 10 个以上文件，加载时报“文件不存在”

旧版本在上传过程中只保留最新 10 个副本。2.12.0 起已改为上传期间不清理，更新即可。

### 一次最多能选多少个文件

面板：5000 个 / 2GB；宿主：10000 个 / 5GB；单文件 512MB。超过会在上传前提示。

### 只有 100 个名额

旧版本的客户端上限，2.12.0 已移除。现在按 5000 个 / 2GB 判断。

### 上传进度一直不动

大批量（例如 2019 个）会逐个上传，面板显示 `上传中 123/2019`。文件多、单个大时会久一点；不要重复点。

### 解析进度一直停在 0%

单个超大 JSON（例如 174MB 的 `conversations.json`）在 `JSON.parse` 期间无法更新界面，解析完会直接到 100% 并消失。ZIP 是逐条目进度，会正常走。

### 文件被跳过

- 不是 DeepSeek 网页对话（例如 ChatGPT 导出）
- JSON 损坏、空文件
- ZIP 加密 / ZIP64 / 解压失败 / 超过条目或大小上限
- 未知的官方导出版本（例如 v4）
- 文件缺失

跳过项会在状态行显示数量，点「详情」看原因；不影响同批其它文件。

### 附件没有导入

- 只有新版官方 v3 包里有附件本体；旧版导出和浏览器记录只有文件名/签名链接
- 单个附件超过 64MB、在 ZIP 里缺失、路径不安全时会被跳过
- 导入结果会显示“X 个附件未导入”

### 最近列表里有文件，但点开说文件不存在

2.12.2 起最近列表只显示仍存在的文件；点击失效条目失败时也会自动刷新。若仍遇到，刷新页面再试。

### 官方 ZIP 里的 `user.json`

插件忽略它，不读取、不导入。

## 识别

### ChatGPT / Claude 导出被拒绝

预期行为。插件只认 DeepSeek 网页对话，避免误导入其它 AI 的内容。

### 官方对话被误判为无法识别

- 新版：确认有 `id`、`messages` 数组、`current_message_id`，且消息带 `role` 和 `fragments`
- 旧版：确认有 `id`、`mapping`，且节点 `message.fragments` 里至少一个 `type` 是 `REQUEST` / `RESPONSE` / `THINK`
- 只有 `mapping` 但没有 fragments 的，会被当成其它 AI

### 提示“官方导出 vN 暂不支持”

插件只认已实现的官方导出版本（当前是 v3）。更新插件后再试；不要把未知版本改个文件名硬塞进来。

## 合并与重复

### 两个相同的 ZIP 为什么只有一份对话

按 id 去重；内容相同就保留先读到的一份，面板显示“出现在多个来源里”的对话数，不是漏读。

### 旧文件里被删除的对话还在

默认取并集，并标「只出现在较早导出」。导出没有删除标记；只想要当前状态就只选最新那份。

### 标题相同却被当成两段

身份只看 id，不看标题。标题相同、id 不同就是两段。

### “无法判断”是什么意思

同一 id、`updated_at` 相同、聊天内容不同，且无法按日期/长度分出胜负。保留第一份并计数，避免结果不确定。

### 旧导出和新导出混选，为什么有的还用旧格式

两份聊天内容相同就保留先读到的一份，不算更新；只有内容真的变了才采用较新版本。

## 版本与分支

### 打开为什么停在最新，而不是最长

初始优先「当前版本标记」，没有就取最新叶子；切换版本后才走最长后续。

### 想要最长分支

导入设置的版本选项选「消息最多的版本」，或在逐条选择里切换。

### 已选的版本想改

设置里点「重选」；会停在上次选的位置。

## 费用与摘要

### 预估和实际差很多

预估是启发式，受模型、缓存、语言比例影响。校准会逐步贴近；连续偏差大时检查 `docs/cost.md` 的参数与校准说明。

### 预估价是高峰还是空闲

按当前时刻判断；面板会标「按高峰价计」或「按空闲价计」。

### 摘要中途失败

- 每个分块失败会自动重试一次
- 如果第一段就失败：本次导入失败，不生成会话；错误会显示块号和轮次范围
- 如果后面的段失败：前面已经生成的摘要会保留，写成部分摘要；结果卡片会显示失败块、原因和重试次数，`manifest.json` 也会记录 `summary.partial` 与 `summary.failure`
- 部分摘要不会自动补全失败段；可以重新导入该对话，或改用「完整存档」保留全文

### 超过费用上限

预估超过上限时不会调用模型，会直接改为只保留最近对话。检查摘要模型配置或提高费用上限；也可以改用「不保留」「完整存档」，两者都不调用模型。

### 摘要思考强度在哪改

摘要默认 `Off`。每次摘要导入时在导入设置里选择 `Off / Low / High / Max`；插件配置里的「默认思考强度」只决定初始值，开发者配置里已经没有这个字段。选择非 `Off` 后推理 token 按输出计费，当前费用预估不包含这部分，实际费用会更高。

### 记忆文件在哪

摘要或完整存档成功后，工作区里会有：

```text
deepseek-memory/
  manifest.json
  memory.md
  thinking.md   # 可选
```

不保留和全部保留不生成记忆文件。大文件会拆成 `memory-0001-0400.md` 等分片。

### 旧版本留下的 md 文件

旧导入可能生成过 `deepseek-import-summary.md` / `deepseek-import-record.md`。新版本不再生成，也不会自动删除旧文件；确认不需要后可以手动删。

### 旧工作区为什么能给出更低估价

同计划会复用上次真实用量按缓存命中价估算；旧记录只有实际费用时也会作为参考。

## 导入过程

### 可以中途停止吗

可以。弹窗选择：继续、保留已完成部分并停止、停止并丢弃。

### 工作区为什么带 (2)

同一标题重复导入会自动编号，避免覆盖。

### 导入后会话能继续聊吗

可以。写入的是 DSH 原生会话，打开后选模型继续。

### 导入失败提示“会话格式自检失败”

说明当前 DSH 版本的会话格式与插件预期不一致；先升级 DSH/插件，仍失败请附版本与错误详情反馈。

## 安装

### 侧栏没有「导入」

- 确认安装命令成功
- 确认装到了当前 profile（WebUI 用 `web`，桌面端用应用内插件管理）
- 重启 DSH / 桌面端，刷新页面

### 桌面端安装到错误位置

桌面端使用 `desktop` profile；不要用 `--profile web`。在桌面应用「插件」页添加，或使用宿主内置 plugin_manager。

## 数据位置

- 上传副本/配置/校准：插件数据目录（Windows `%LOCALAPPDATA%\dsh-deepseek-import`，沿用旧目录名）
- 导入的会话：DSH 会话目录/工作区
- 导入位置：插件配置里可改
