# 官方导出格式对照：2026-11-05（旧） vs 2026-11-25（新）

本文只记录两种官方导出格式的差别，不含实现改动。

样本：

| 项目 | 旧（2026-11-05） | 新（2026-11-25） |
|---|---|---|
| 目录 | `F:\WorkSpace\harness\官方格式\deepseek_data-2026-11-05` | `F:\WorkSpace\harness\官方格式\deepseek_data-2026-11-25` |
| ZIP 大小 | 52,304,521 字节 | 377,353,816 字节 |
| ZIP 条目 | 2 | 3,025 |
| 解压后 | 174,848,911（conversations.json）+ 428（user.json） | 约 521,451,890 字节 |
| 会话数 | 2,017 | 2,034 |
| 消息数 | 约 83,342 个节点 / 81,323 条带 model 的消息 | 82,950 条消息 |

## 1. 包结构

旧：

```text
user.json
conversations.json      # 一个数组，全部会话
```

新：

```text
manifest.json
user.json
chat_session_index.json # 会话清单
chat_sessions/
  <session-id>.json     # 一个会话一个文件
  <session-id>_files/   # 该会话的附件
    <file-id>_<原名>
```

- 新格式新增 `manifest.json`、`chat_session_index.json`、`chat_sessions/` 和附件目录。
- 新 ZIP 3025 条 = 1 manifest + 1 user + 1 index + 2034 会话 JSON + 988 附件，无目录条目，无 zip64。
- 旧 ZIP 只有 2 条：`user.json`、`conversations.json`。

## 2. 版本标识

旧：没有版本字段，也没有 manifest。

新：

```json
{ "export_format_version": 3 }
```

## 3. 会话清单

旧：无。要列出会话必须解析整个 `conversations.json`。

新：`chat_session_index.json`，2034 条，每条：

```json
{ "id": "…", "title": "…", "pinned": false, "message_count": 2,
  "inserted_at": "…", "updated_at": "…" }
```

- 与 `chat_sessions/*.json` 一一对应（2034 = 2034，id 集合完全相等，无重复）。
- 抽查的 3 个会话：index 的 title、message_count、inserted_at、updated_at 与文件内完全一致。
- `pinned` 为新字段，4 个会话为 true。

## 4. 会话对象

旧：`conversations.json` 数组元素：

```json
{ "id": "…", "title": "…", "inserted_at": "…", "updated_at": "…",
  "mapping": { "<节点 id>": { …节点… } } }
```

新：`chat_sessions/<id>.json`：

```json
{ "id": "…", "title": "…", "pinned": false,
  "current_message_id": 2,
  "inserted_at": "…", "updated_at": "…",
  "messages": [ …消息… ] }
```

- 新格式把 `mapping` 换成 `messages` 数组。
- 新格式会话级新增 `pinned`、`current_message_id`。
- 消息的父子关系由每条消息的 `parent_id` 表达，不再有 `children` 数组。

## 5. 消息 / 节点字段

旧节点：

```json
{ "id": "1", "parent": "root", "children": ["2"],
  "message": { "model": "deepseek-reasoner", "inserted_at": "…",
               "fragments": [ … ] } }
```

新消息：

```json
{ "id": 1, "parent_id": null, "role": "USER", "status": "FINISHED",
  "thinking_enabled": false, "search_enabled": true,
  "accumulated_token_usage": 0, "inserted_at": "…",
  "fragments": [ … ] }
```

字段差异：

| 字段 | 旧 | 新 |
|---|---|---|
| 节点 id | 字符串，会话内唯一 | 数字，每个会话从 1 开始 |
| 父节点 | `parent`（`"root"` 或父节点 id） | `parent_id`（数字或 `null`） |
| 子节点 | `children` 数组 | 无，靠 `parent_id` 反查 |
| 角色 | **无**，只能由片段推断 | `role`：`USER` / `ASSISTANT` |
| 状态 | **无** | `status`，5 种（见下） |
| 模型 | `message.model`，只有 `deepseek-chat` / `deepseek-reasoner` | **没有** |
| token 用量 | 无 | `accumulated_token_usage` |
| 思考/搜索开关 | 无 | `thinking_enabled`、`search_enabled` |
| 当前路径 | 无`current_message_id` | 有，2034 个会话中均等于最后一条消息 |

新格式 `status` 取值（82,950 条消息）：

| status | 条数 |
|---|---|
| FINISHED | 75,239 |
| INCOMPLETE | 6,155 |
| CONTENT_FILTER | 1,409 |
| TIMEOUT | 145 |
| CONTEXT_LENGTH_EXCEEDED | 2 |

角色（新格式）：`USER` 39,205 / `ASSISTANT` 43,745。

## 6. 片段（fragments）类型对照

旧格式片段总数与类型（流式统计，整个 conversations.json）：

| type | 条数 | 字段 |
|---|---|---|
| RESPONSE | 41,106 | `content` |
| REQUEST | 38,206 | `content` |
| THINK | 20,442 | `content` |
| TOOL_OPEN | 3,158 | 链接信息 |
| SEARCH | 1,442 | `results:[{url,title}]` |
| FILE | 1,099 | `files:[{file_id,file_name,file_size}]` |
| TOOL_SEARCH | 842 | 搜索结果 |
| TOOL_FIND | 4 | 站内查找 |

新格式片段类型（82,950 条消息的统计）：

| type | 条数 | 字段 |
|---|---|---|
| RESPONSE | 40,407 | `content` |
| REQUEST | 38,931 | `content` |
| THINK | 21,330 | `content`、`elapsed_secs` |
| CONTENT_RISK | 6,950 | `content`、`style`（如 `WARNING`） |
| TOOL_OPEN | 3,322 | `status`、`url`、`title`、`snippet`、`site_name`、`published_at`、`site_icon`、`stage_id` |
| TOOL_SEARCH | 2,340 | `queries[]`、`results[]`、`status`、`stage_id` |
| TEMPLATE_RESPONSE | 1,555 | `content` |
| FILE | 1,150 | `files:[{id,file_name,file_size,token_usage,inserted_at,export_path,is_image,width,height}]` |
| PARTIAL_FILE_READ | 8 | `ratio` |
| READ_LINK | 7 | `results[]` |
| TOOL_IMAGE_SEARCH | 6 | `status`、`results[]`、`stage_id` |
| TOOL_FIND | 4 | `status`、`pattern`、`stage_id` |
| TIP | 2 | `content`、`style` |

要点：

- 新格式 **没有** `SEARCH`，相关能力拆成 `TOOL_SEARCH` / `TOOL_OPEN` / `TOOL_FIND` / `TOOL_IMAGE_SEARCH` / `READ_LINK`。
- 新格式新增 `CONTENT_RISK`、`TEMPLATE_RESPONSE`、`TIP`、`PARTIAL_FILE_READ`。
- `THINK` 新增 `elapsed_secs`。
- 核心正文/提问仍是 `REQUEST` / `RESPONSE` / `THINK` 三种，内容字段都是 `content`。
- 单条消息最多 38 个片段。

## 7. 附件

旧：`FILE` 片段只有文件元信息（`file_id`、`file_name`、`file_size`），ZIP 里 **没有文件本体**，附件无法恢复。

新：附件随包导出。

- 位置：`chat_sessions/<session-id>_files/<file-id>_<原文件名>`
- `FILE` 片段用 `export_path` 指向附件（相对 ZIP 根），另有 `is_image`、`width`、`height`、`token_usage`
- 本样本 988 个附件分布在 152 个 `_files` 目录，最大 9.6MB
- 4 个中文文件名，ZIP 内带 UTF-8 标记

## 8. 树与分支

旧：

- `mapping` 图：`parent` + `children`。
- 根节点写法不统一：`"parent":"root"` 2,714 处，`"parent":null` 2,019 处。
- 节点 83,342 个，其中带 `model` 的消息 81,323 条（约 2,019 个节点没有 model，与 `parent:null` 数量接近，未逐条确认）。
- 没有 `current_message_id`，导出本身不记录当前选中的分支。

新：

- 消息数组 + `parent_id`，`parent_id:null` 为根。
- 2034 个会话的 `current_message_id` 都等于最后一条消息。
- 80,211 条父子引用全部有效，0 条断链。
- 消息 id 为数字，每个会话独立编号。

## 9. 时间格式

旧：`2026-04-04T00:55:44.269000+08:00`（6 位小数 + 时区偏移）

新：`2025-09-21T06:50:02.912Z`（3 位小数 + UTC）

`Date.parse` 和插件现有的 `parseTime` 对两种格式都能得到正确时间戳（实测 4 个样本）。

## 10. user.json

- 新旧结构相同：`user_id`、`email`、`mobile{mobile_number,area_code}`、`oauth_profiles[]`。
- 两者字节数都是 428，但内容不完全相同（账号资料有更新，与格式无关）。

## 11. 字段差异总表

| 类别 | 旧格式 | 新格式 |
|---|---|---|
| 版本 | 无 | `manifest.json`：`export_format_version: 3` |
| 会话清单 | 无 | `chat_session_index.json` |
| 会话容器 | `mapping` 字典 | `messages` 数组 |
| 节点 id | 字符串 | 数字 |
| 父级 | `parent` + `children` | `parent_id` |
| 根 | `"root"` / `null` 两种 | `null` |
| 当前分支 | 无 | `current_message_id` |
| 会话级 `pinned` | 无 | 有 |
| 消息角色 | 无 | `role` |
| 消息状态 | 无 | `status`（5 种） |
| 消息模型 | `model` | 无 |
| token 用量 | 无 | `accumulated_token_usage` |
| 思考/搜索开关 | 无 | `thinking_enabled` / `search_enabled` |
| 片段类型 | 8 种 | 13 种 |
| `THINK` 耗时 | 无 | `elapsed_secs` |
| 文件片段 | 只有元信息 | 元信息 + `export_path` 等 |
| 附件本体 | 无 | 有（`_files/`） |
| 时间格式 | 本地时区 + 微秒 | UTC + 毫秒 |

## 12. 对现有解析器的影响（仅记录，未改动）

1. `lib/conversation.js` 的 `classifyValue` 只认 `mapping` 结构和 `{data:{chat_session,chat_messages}}` 结构，新格式的 `{id,title,messages}` 会被判成“通用消息数组”而跳过。
2. `lib/zip.js` 的 `MAX_ENTRIES = 200` 与新 ZIP 的 3025 条冲突，会直接报“zip 里的文件太多”；同时当前实现整包读入内存。
3. 新格式自带 `role`、`status`，现有代码对新格式仍需按片段推断角色，且没有状态概念。
4. 新格式附件可随包导入；现有代码只把 `FILE` 当作无内容片段忽略。

## 13. 未覆盖 / 边界

- 未逐会话对比新旧消息条数（两次导出相隔 20 天，消息数变化属于内容差异，不是格式差异）。
- 稀有片段（`TIP`、`READ_LINK`、`PARTIAL_FILE_READ`、`TOOL_IMAGE_SEARCH`、`TOOL_FIND`）只统计了类型、条数和字段名，未逐个打开样本确认语义。
- `export_format_version` 只见到 3，未来版本行为未知。
- 旧格式根节点 `"root"` 与 `null` 混用未逐会话确认原因。
- 未校验每个 `export_path` 在 ZIP 中都存在（需要遍历全部会话，本轮未做）。
